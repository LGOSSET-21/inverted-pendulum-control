# Agent V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a reproducible experimental supervisor that tunes the existing massive-rod LQR and measures its performance against the original controller and random search.

**Architecture:** Add `src/agentic` around the existing physical model and RK4 integrator. Share one validated experiment store and four tools between offline coordinate search and an optional LLM policy. Keep held-out evaluation outside the tuning session.

**Tech Stack:** Python, NumPy, SciPy, standard-library unittest/JSON/dataclasses; optional OpenAI SDK; existing Node physics regression tests.

**Spec:** `docs/superpowers/specs/2026-10-10-agent-v1-design.md`

## Global Constraints

- Baseline `6f8576c51280a6453c36e10de592b7d4af18e20d` is preserved on remote `baseline/pre-agent-v1`; work on `feat/agent-v1`, never rewrite or merge into main.
- Keep existing entry points, saved trajectories, and visualizations compatible.
- Use `massive_rods.Model(rod_mass=0.01)` and the existing RK4 integration routine.
- Default duration is 12 s and step is 0.0025 s. Saturate controller force at 8 N; terminate at the original 60-degree tilt or 2 m track limits.
- Four LQR scale factors are bounded to [0.1, 10]; all ones reproduce the original controller.
- Settling thresholds: 0.02 m, 0.03 m/s, 1 degree, 0.05 rad/s, with one full second of observation through the end of the run.
- Default budgets: 12 candidate evaluations including baseline, and 60 tool calls per session.
- JSONL logs preserve failures and source/settings provenance, use strict JSON, and exclude credentials.
- Benchmark uses the four tuning and four validation scenarios specified in the spec, with equal candidate budgets for adaptive and random search.
- No swing-up changes, global stability claims, or guaranteed performance improvement.

## Review Focus

- Nonfinite or boolean numeric inputs, off-grid pulse boundaries, and duration shorter than pulse: reject before simulation (Task 1).
- Initial state already outside limits and exceptions before the first integration step: record failures without misleading settling or nonfinite JSON (Tasks 1–2).
- Unknown IDs, path-like IDs, extra tool arguments, and malformed model JSON: reject without filesystem escape or resetting budgets (Tasks 2–3).
- Output-directory collisions and interrupted/API-failed sessions: retain earlier artifacts and complete events (Tasks 2–3).
- Early agent termination and validation leakage: compare actual equal search budgets and keep held-out results out of selection (Task 4).

## File map

- `src/agentic/simulation.py`: validated parameters/scenarios and reusable simulator.
- `src/agentic/metrics.py`: objective measurements and candidate ranking.
- `src/agentic/scenarios.py`: immutable tuning and validation definitions.
- `src/agentic/store.py`: unique output directories, provenance, logs, and trajectory artifacts.
- `src/agentic/tools.py`: four-tool dispatch, validation, budgets, recorded winner.
- `src/agentic/agent.py`: offline adaptive policy and provider-independent model loop.
- `src/agentic/llm.py`: optional OpenAI transport and tool schemas.
- `src/agentic/benchmark.py`: random comparator, held-out evaluation, refinement, reports.
- `src/agentic/__init__.py`, `src/agentic/__main__.py`: public interface and CLI.
- Four `tests/test_agentic_*.py` files: numerical, store/tools, policy, and benchmark tests.
- `requirements-agent.txt`, `.gitignore`, `README.md`: optional installation, generated-run exclusions, and user instructions.
- `results/agentic/benchmark.json` and `results/agentic/benchmark.md`: compact real result with provenance.

## Task 3: Offline policy, LLM loop, and runnable CLI

**Files:** Create agent.py, llm.py, __main__.py, requirements-agent.txt and tests/test_agentic_agent.py.

**Interfaces:**
- `run_offline(tools) -> dict`: baseline first; repeatedly propose one bounded factor change around the best measured candidate, cycle four axes and multipliers 2 then 0.5, retain best, shrink exploration toward 1 after a nonimproving cycle; stop on budget. Report policy name and selected experiment ID.
- `run_llm(tools, transport, *, model: str) -> dict`: same baseline-first and bounded tool loop; `transport.respond(messages, tool_schemas, model)` returns normalized text and tool calls. Provider-specific response objects never enter core policy.
- `OpenAITransport`: lazy optional SDK import, explicit model, credential from environment; finite request timeout and bounded retries.
- CLI: `PYTHONPATH=src python -m agentic tune --policy offline --budget 12 --output runs`; `--policy llm --model MODEL` opts into API use; benchmark command added in Task 4.
